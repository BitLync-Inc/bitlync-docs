OpenAPI 0.83.0

GET|PUT /isv/experience-config sets category config for PSA, RMM, Docs, CS, and Commerce, plus recommended grants and branding. Vendors inherit the category template. Access is List, Read, and Write, and those stack. Never is its own setting. The MSP can tighten the starting verbs. Sandbox Experience Preview (POST /connect/sessions/preview and console #/experience) walks Connect after Save: keys, grants, boards, map, done. Getting Started on Setup is Suggest, Save, Preview, then Use MCP or Use API. After Save, copy-paste prompts follow the saved profile. Partner credentials and Production MSP Connect keys are separate. Connections lists each MSP and vendor, last sync, and sync detail. Issues gives a support blurb and a redacted request debug.

Company update is POST /tenants/{tenant_id}/companies/write with vendor_native, when the MSP has turned on psa.company.update. A missing grant is grant_missing. If the update does not run, the code is psa_company_update_refused.

Machine API auth is X-API-Key. Console login is a magic link or Sign in with Microsoft, for an email that is already seated or invited.

Tickets

Tickets are two-way when the MSP grants it. You can create, update, and close. You can subscribe to events when the MSP changes the ticket in their PSA. Grants: psa.ticket.create, psa.ticket.update, psa.ticket.events. When a ticket is created, updated, noted, closed, or reopened, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=ticket.closed (also created, updated, noted, reopened). Optional signed webhook. Grant is the connection (psa.ticket.events). Missing is grant_missing. When a device is created or updated, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=device.updated (also created). Optional signed webhook. Grant is the connection (rmm.device.events). Missing is grant_missing. When a company is created or updated, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=company.updated (also created). Optional signed webhook. Grant is the connection (psa.company.events). Missing is grant_missing. You can close a ticket once they accept the connection. Auto-close when a finding is fixed is a separate switch. Hours are a write, not a read. Required member is the picker id from GET /tenants/{tenant_id}/members. Create and update accept optional board, status, and priority list ids (GET …/ticket-boards, ticket-statuses, ticket-priorities on ConnectWise and Halo); unknown id → 422. Autotask uses queues, statuses, and priorities (GET …/ticket-queues). dry_run defaults true.

Ticket

GET and POST /tenants/{tenant_id}/tickets. Tickets are two-way when the MSP grants it. You can create, update, and close. You can subscribe to events when the MSP changes the ticket in their PSA. When a ticket is created, updated, noted, closed, or reopened, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=ticket.closed (also created, updated, noted, reopened). Optional signed webhook. Grant is the connection (psa.ticket.events). Missing is grant_missing. When a device is created or updated, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=device.updated (also created). Optional signed webhook. Grant is the connection (rmm.device.events). Missing is grant_missing. When a company is created or updated, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=company.updated (also created). Optional signed webhook. Grant is the connection (psa.company.events). Missing is grant_missing. You can close a ticket once they accept the connection. Auto-close when a finding is fixed is a separate switch. Time takes hours and a required member. The member is the picker id from GET /tenants/{tenant_id}/members. Board, status, and priority on create and update take ids from the ConnectWise and Halo lists. Autotask uses ticket-queues, statuses, and priorities. An unknown id returns 422.

Company

POST /tenants/{tenant_id}/companies. Pax8 matches a company it already has, then creates the rest. Company create runs when the MSP turns on the grant. Match runs first. Two matches return company_match_ambiguous. Exact-name auto-Match fills Match. Ambiguous names stay Needs match. Each unmatched row is Match, company import from PSA, or Skip. Company import creates the customer in the ISV after a dry_run preview. Contacts are list and match. POST /tenants/{tenant_id}/companies/write updates custom fields on an existing company via vendor_native when psa.company.update is on.

Member

GET /tenants/{tenant_id}/members. PSA people for the time picker (ConnectWise System Members; Halo Agents; Autotask Resources). Public word is always member. Halo and ConnectWise list members when that permission is on. Autotask lists Resources as members. A missing ConnectWise members permission can return 403. Time write uses the listed id as CreateTimeEntryBody.member.

GET /tenants/{tenant_id}/devices.

Agreement

GET /tenants/{tenant_id}/agreements. Recurring MSP service billing arrangement. The public word is Agreement.
