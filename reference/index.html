Reference

Routes that exist today.

Auth is the X-API-Key header. Writes take dry_run (default false; writes are real). Import the OpenAPI file. This page is not the spec.

OpenAPI 0.100.0. Alert catalog, send, test, routing, snooze, and billing CSV bodies are typed. Field names are the schema titles on Alerts and What we write.

Billing quantities: POST /tenants/{tenant_id}/billing/quantities. The MSP matches the line. You send an absolute quantity (0 stops billing) on your cadence (daily or monthly). The MSP's change limit defaults to 25%. A change over that limit waits. Ending a line is refused. Each row takes optional trial_end_date, an ISO date YYYY-MM-DD or null. Trial ending, Trial converted, and Trial expired use it. Omit it and the stored date stays. A bad date fails that row.

request
{
  "idempotency_key": "docs-probe-1",
  "dry_run": true,
  "quantities": [
    {
      "customer_ref": "cust-42",
      "customer_name": "Brightside Pediatrics",
      "service": "managed-edr",
      "quantity": 44
    }
  ]
}
response
{
  "tenant_id": "sandbox-mainstreet",
  "results": [
    {
      "tenant_id": "sandbox-mainstreet",
      "customer_ref": "cust-42",
      "service": "managed-edr",
      "quantity": "44.0000",
      "previous_quantity": null,
      "status": "not_mapped",
      "reason": "customer_not_matched",
      "dry_run": true,
      "sandbox": true
    }
  ],
  "counts": { "not_mapped": 1 },
  "dry_run": true,
  "sandbox": true
}

The request matches BillingQuantitiesBody. trial_end_date is optional on each row and this example omits it. The response is the sandbox body for that request when the customer is not matched yet. The 200 schema is an object.

SDK 2.0.0 (breaking): the generated Python and TypeScript clients now return typed response models where the spec declares one (for example TicketList) instead of plain dicts. Read attributes (listed.sandbox) or call .to_dict().

GET|PUT /isv/experience-config sets category config for PSA, RMM, Docs, CS, and Commerce, plus recommended grants and branding. Vendors inherit the category template. Access is List, Read, and Write, and those stack. Never is its own setting. The MSP can tighten the starting verbs. Sandbox Experience Preview (POST /connect/sessions/preview and console #/experience) walks Connect after Save: keys, grants, boards, map, done. Getting Started on Setup is Suggest, Save, Preview, then Use MCP or Use API. After Save, copy-paste prompts follow the saved profile. Partner credentials and Production MSP Connect keys are separate. Connections lists each MSP and vendor, last sync, and sync detail. Issues gives a support blurb and a redacted request debug.

Halo and ConnectWise company custom fields: POST /tenants/{tenant_id}/companies/write writes a value on an existing company with vendor_native, and ensure_custom_field creates the missing field definition. The field works live on Halo and ConnectWise. It is created once in your stack under the MSP's standing psa.company.field.create grant, and an existing field with the same label is reused. The field label shows on Configure. Value writes use the psa.company.update grant, off by default. A missing grant is grant_missing. If the update does not run, the code is psa_company_update_refused.

Machine API auth is X-API-Key. Console login is a magic link or Sign in with Microsoft, for an email that is already seated or invited.

Tickets

Tickets are two-way when the MSP grants it. You can create, update, and close. You can subscribe to events when the MSP changes the ticket in their PSA. Grants: psa.ticket.create, psa.ticket.update, psa.ticket.events. When a ticket is created, updated, noted, closed, or reopened, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=ticket.closed (also created, updated, noted, reopened). Optional signed webhook. Grant is the connection (psa.ticket.events). Missing is grant_missing. When a device is created or updated, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=device.updated (also created). Optional signed webhook. Grant is the connection (rmm.device.events). Missing is grant_missing. When a company is created or updated, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=company.updated (also created). Optional signed webhook. Grant is the connection (psa.company.events). Missing is grant_missing. You can close a ticket once they accept the connection. Auto-close when a finding is fixed is a separate switch. Hours are a write, not a read. Required member is the picker id from GET /tenants/{tenant_id}/members. Create and update accept optional board, status, and priority list ids (GET …/ticket-boards, ticket-statuses, ticket-priorities on ConnectWise and Halo); unknown id → 422. Writes are real by default.

GET and POST /tenants/{tenant_id}/tickets. Tickets are two-way when the MSP grants it. You can create, update, and close. You can subscribe to events when the MSP changes the ticket in their PSA. When a ticket is created, updated, noted, closed, or reopened, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=ticket.closed (also created, updated, noted, reopened). Optional signed webhook. Grant is the connection (psa.ticket.events). Missing is grant_missing. When a device is created or updated, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=device.updated (also created). Optional signed webhook. Grant is the connection (rmm.device.events). Missing is grant_missing. When a company is created or updated, you can list those events or get a signed webhook. After a tenant sync, GET /tenants/{id}/connections/events?kind=company.updated (also created). Optional signed webhook. Grant is the connection (psa.company.events). Missing is grant_missing. You can close a ticket once they accept the connection. Board, status, and priority on create and update take ids from the ConnectWise and Halo lists. An unknown id returns 422.

Company

POST /tenants/{tenant_id}/companies. Pax8 matches a company it already has, then creates the rest. PSA company create is not supported: companies are created by the MSP, and a PSA create returns 403 company_create_not_supported. Exact-name auto-Match fills Match. Ambiguous names stay Needs match. Each unmatched row is Match, company import from PSA, or Skip. Company import creates the customer in the ISV after a dry_run preview. Contacts are list and match. POST /tenants/{tenant_id}/companies/write writes a Halo or ConnectWise company custom-field value on an existing company via vendor_native, and ensure_custom_field creates the missing field definition. The field works live on Halo and ConnectWise. It is created once in your stack under the MSP's standing psa.company.field.create grant, and an existing field with the same label is reused. The field label shows on Configure. Value writes use the psa.company.update grant, off by default.

Member

GET /tenants/{tenant_id}/members. PSA people for the time picker (ConnectWise System Members; Halo Agents). Public word is always member. Halo and ConnectWise list members when that permission is on. A missing ConnectWise members permission returns 502 upstream_auth_failure. Time write uses the listed id as CreateTimeEntryBody.member.
