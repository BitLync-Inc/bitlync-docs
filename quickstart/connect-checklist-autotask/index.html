Quickstart

Autotask Connect checklist

Autotask words. For the MSP connecting so an ISV can use Bitlync. Queues not boards. Fixture/docs path — live Hub prove is gated elsewhere.

Production badge OFF. Contact create stays parked (list/match only). PSA company create refused. Never mint an agreement header. Never invent boards for Autotask.

Before you start

  • ISV has a Bitlync key and a tenant for this MSP
  • MSP can create an Autotask API User (system) and copy username, secret, and API tracking ID
  • MSP pastes keys into Bitlync Connect (hosted). The ISV never sees those keys
  • Expect fixture-first lists and dry_run writes until a live Hub path is proven (do not treat this checklist as a Hub join ask)

1. Open Connect

  • MSP opens the hosted Connect link for Autotask
  • MSP accepts MSP Connect Terms before keys save
  • Follow the numbered guide: create API user → check security level → paste into Bitlync step 2
  • Fields: username, secret, API tracking ID (ApiIntegrationCode), optional base URL (leave blank to resolve zone)

2. Keys and permissions

  • Paste credentials (no OAuth / Authorize for Autotask)
  • Bitlync tests the connection in the flow
  • If something is missing, fix the named permission on the API user security level, then re-test
  • Read / Write / Never on the card: lists ship; writes stay dry_run / fixture where true

3. Map companies (Match / company import from PSA / Skip)

PSA companies are the book. Bitlync does not create companies in Autotask.

  • Same Match / company import from PSA / Skip outcomes as Halo and ConnectWise
  • Exact-name auto-Match fills Match only — never auto-import; ambiguous → Needs match

4. Contacts and members (list / match)

  • Contacts: list and match under mapped companies — no create
  • Members: Autotask Resources map to canonical member ids (fixture-first)
  • Empty list stays empty — never invent a member

5. Queues / statuses / priorities (not boards)

  • Confirm Bitlync can list Autotask queues, statuses, and priorities
  • Public routes: GET …/ticket-queues, ticket-statuses, ticket-priorities
  • ticket-boards stays unsupported for Autotask — never call a queue a board
  • Ticket / time writes: preview with dry_run on the fixture path; live Autotask HTTP apply stays off until Hub prove

6. Smoke check (fixture / dry_run)

  • Companies: Match and/or company import from PSA for the rows you care about
  • Contacts list/match; members list (Resources)
  • Queues / statuses / priorities list
  • Ticket or time: dry_run preview only on this path
  • Agreement lines only on an existing Contract — no new agreement header
  • Production badge stays OFF

Never on this path

  • Create a company in Autotask
  • Contact create (parked)
  • Mint an agreement or project header
  • Invent CW-style boards for Autotask
  • Invent OAuth / Authorize
  • Turn on an Autotask production badge yourself
  • Treat Connect as an Autotask Hub join ask

Halo + ConnectWise first-customer path: Connect checklist (Halo/CW). Coverage matrix: Coverage. Sandbox curl day-one: Quickstart.
