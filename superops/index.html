Connectors

SuperOps.

One SuperOps connection covers PSA and RMM.

One connection, two categories

SuperOps is a unified PSA and RMM. The MSP connects it once and it shows under both Service desk (PSA) and RMM on Connect step 1. It is not a Documentation connector. It uses the SuperOps MSP GraphQL API; your calls stay on the normal Bitlync routes and canonical objects.

SuperOps statuses and priorities are names the MSP can customize. Stock names map to canonical values; anything else comes back as unknown, never guessed.

Bitlync does not create SuperOps clients. Writes take dry_run and are real by default. In production, the MSP's grant during Connect is the approval; without the grant for an operation, the call is refused (grant_missing).

Token setup (MSP)

Use a limited technician user, not an admin. A SuperOps API token acts as the user who generated it and carries that user's role.

  1. As a SuperOps admin: Settings → Technicians → Add technician. Name it Bitlync and give it a limited role with only tickets, clients, contracts, and custom fields. Not administrator.
  2. Log in as the Bitlync technician. Settings → My Profile → API token → Generate Token. Copy it before leaving the page. Never generate it as an admin.
  3. Copy your subdomain from Settings → My MSP → MSP Information (the first part of acme.superops.ai; pasting the full address is fine).
  4. Pick your region: US, or EU if your SuperOps account is hosted in the EU data center.
  5. Paste the token, subdomain, and region into Bitlync Connect, then Authorize.
  • A wrong region looks like an invalid token. Check the region first.
  • SuperOps allows one active token per user. Regenerating it invalidates the old one, so update it in Connect afterwards.
  • The token is stored in the Bitlync credential vault, encrypted at rest, never logged, and never returned to any caller.
